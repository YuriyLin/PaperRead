# 設計取捨

改介面前先讀這裡，別把已經想清楚的事改回去。

## 借鑑的開源專案

用 `gh repo view` 核過倉庫和簡介；只借互動思路，沒有拷程式碼。KaTeX（MIT）是唯一打包進來的第三方程式碼，在 `assets/vendor/katex/`。

| 專案 | 它怎麼做 | 這裡怎麼用 |
|---|---|---|
| [hypothesis/client](https://github.com/hypothesis/client) | 批註用「原話 + 前後文」（TextQuote）錨到網頁文字，頁面改了也儘量找回；找不到的批註標為孤立，不丟 | 劃線和筆記存 `quote/prefix/suffix`；譯文改動後找不到原話，卡片註明「譯文已改」，筆記仍掛在段落上 |
| [zotero/reader](https://github.com/zotero/reader) | 閱讀器裡劃線、評論、側欄彙總，點批註跳回頁面位置 | 左側抽屜「筆記」頁彙總全部討論和筆記，可篩「待回答」，點選跳回並閃爍提示 |
| [edwardtufte/tufte-css](https://github.com/edwardtufte/tufte-css) | 寬屏時旁註放在正文右側留白，窄屏收成可點開的標記 | AI 討論和筆記做成邊注，貼著對應段落；窄屏或開啟原頁時收成段尾角標，點開顯示在段落下方 |
| [allenai/scholarphi](https://github.com/allenai/scholarphi) | 在論文原位懸停看引用、符號定義，不用翻到文末 | 引用號懸停看參考文獻；「公式 (4) / 表 2 / 第 2.2 節」懸停預覽、點選跳轉 |
| [immersive-translate](https://github.com/immersive-translate/immersive-translate) | 段落級雙語對照，可整體切換 | 「譯文 / 對照」兩種模式，外加逐段「原」按鈕只展開這一段英文 |
| [agentcooper/react-pdf-highlighter](https://github.com/agentcooper/react-pdf-highlighter) | 在 PDF 頁面圖層上框出批註區域 | 原頁面板用字元座標框出當前段落的位置（`layout.json`） |
| [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next) | 譯論文時保護公式和版式，雙語對照 | 公式不走文字翻譯，按原 PDF 用 TeX 重排；原頁始終可看 |
| [markmap](https://github.com/markmap/markmap) | 將 Markdown 階層直接渲染為互動式 SVG 心智圖 | 論文結構與思路視覺化；左側 Tiptap 大綱與右側心智圖即時雙向聯動 |

不採用：
- **把譯文塞回 PDF 原版式**：中文排不進英文版面，行寬和字號都不適合長讀；排版錯亂且無法自適應不同裝置。
- **沒有配置引擎時的「問 AI」按鈕**：沒有模型就是假按鈕，所以引擎為「不翻譯」且無 API Key 時這些按鈕不出現。
- **圖表強制自動裁剪**：模型裁剪常誤切子圖標號、圖例或座標軸；採用保留完整版面的「全頁原頁燈箱」，精確高亮目標區域並支援自由縮放檢視完整上下文。

翻譯引擎預設支援本機 Claude Code、OpenAI 相容介面、Gemini、DeepSeek 及本地 Ollama（完全離線且免費）。

## 核心模組的設計取捨

### 1. 原頁燈箱（Lightbox）與版面定位
- **為什麼不依賴自動截圖**：跨欄圖表、多子圖（(a), (b), (c)）與長圖題注在自動裁切時極易失真或截斷。
- **實現**：保留原始高解析度頁面圖檔，點擊圖表或段落定位時喚起滿版燈箱（Lightbox），並按 `layout.json` 歸一化座標自動捲動至視窗正中並框選高亮。支援滑鼠滾輪縮放、平移與單鍵關閉，不打斷閱讀心流。

### 2. 桌面多分頁與左右雙欄（Tabs & Split View）
- **記憶體控制**：Electron 或多標籤瀏覽器若同時渲染大量 PDF 解析頁面，記憶體消耗極大。
- **實現**：建立多分頁管理容器。背景超過 5 個非作用中標籤時，自動休眠其 WebContents 狀態並卸載重型 DOM 節點，保留滾動位置快照；切換時毫秒級就地喚醒。支援 50/50 左右分割視窗，便於對比同領域兩篇文獻的推導細節。

### 3. 跨論文關鍵字雙欄檢索（Master-Detail Split）
- **版面**：寬螢幕流體佈局，左欄固定寬度（約 320px）展示關鍵字庫與精簡動作選單，右欄自適應展開檢索結果卡片。
- **雙向檢索**：只輸入中文譯名或只輸入英文術語皆可自動對稱匹配與關聯檢索。
- **微互動與渲染**：去除清單重複按鈕，改為 Hover 浮動選單與即時行內編輯（Inline Edit）；檢索結果引文支援 KaTeX 數學公式即時渲染，段落匹配關鍵字呈暖黃螢光高亮。

### 4. 論文深度剖析（Deep Technical Audit）
- **拒絕籠統摘要**：大模型生成「本文提出了一種新穎的方法…」此類讚美式公文套話對研究者毫無價值。
- **五維批判性審查**：
  1. 核心主張與證據對照（Claim-Evidence 嚴格對齊，揭露誇大）
  2. 消融實驗審查（Ablation Audit，核心架構 vs 工程 Trick）
  3. 關鍵公式拆解與數值示範（Toy Example，具體張量維度與前向步進）
  4. 基準線公平性與數據審查（Baseline 強度、算力開銷與數據洩漏檢驗）
  5. 局限性、邊界與盲點（Failure Modes、分佈外 OOD 與真實失效場景）

### 5. 雙向同步心智圖（Tiptap + Markmap）
- **痛點**：純純視覺心智圖無法精細編輯長文字，純文字大綱又缺乏全景直觀感。
- **實現**：左側採用無干擾 Tiptap 樹狀編輯器，右側採用基於 D3 / Markmap 的向量 SVG 心智圖。任何一端的拖曳、收合、節點重命名或階層調整，均以毫秒級事件無縫同步至另一側。

### 6. 手寫筆跡與圖章貼紙（Ink & Stickers）
- **錨定機制**：絕對像素座標在改變字號、版心或換螢幕時必定錯位。
- **實現**：向量筆劃（SVG path）與幾何貼紙一律綁定正文段落 `anchor`（塊 id），並記錄基準點位移與段落文字雜湊 `textHash`。即使字號縮放或版心調整，筆跡與圖章依然緊貼目標詞句。

### 7. Obsidian 六大工作目錄與受管區塊防護
- **痛點**：重覆匯出知識庫時，常常覆蓋掉讀者在筆記軟體中手動撰寫的心得。
- **實現**：嚴格劃分 `01` 到 `06` 六大專題資料夾，匯出筆記內使用 `<!-- paperread:managed:start -->` 與 `<!-- paperread:managed:end -->` 邊界標記。重新同步時僅增量覆蓋受管區塊，使用者在此標記之外補充的筆記與 WikiLinks 100% 完整保留。

## 閱讀介面互動規範

- **頂欄常駐**：不隨滾動收起。返回文獻庫、目錄、雙語對照、原頁定位、筆記抽屜、字號調節與儲存狀態隨時可見。
- **段落點擊即操作**：點擊段落浮現簡潔操作條（劃線、提問、筆記、查看原頁）；鍵盤支援 `J`/`K` 移動當前段落，快捷鍵直接操作。
- **選中文字工具列**：四色劃線、行內筆記、提問 AI、查看英文、複製引用。
- **邊注與側欄抽屜**：邊注緊貼對應段落右側（寬螢幕），適合浸潤式研讀；右側抽屜彙總全文所有批註、問題與整篇筆記，適合全域複習。

## 排版與色彩規範

### 版面
- 一欄正文，約 35 個漢字一行（`--measure: 35em`，18px 時約 630px），行距 1.9，段間距約一行。
- 中文兩端對齊，手機改左對齊以避免長英文單詞撐開字距。
- 正文預設思源宋體（Noto Serif SC / TC），可切換黑體；英文原文使用襯線字型，左側細線標註，形成分明閱讀階層。
- 數字統一等高（lining），表格統一採用書籍式三線表，絕無多餘縱向分割線。
- 長公式與寬表格先按比例縮小（桌面最小 72%），超寬則支援塊內平滑滾動，整頁永遠不橫向跑版。

### 色彩系統
暖白紙色底（`#f6f3ec`），墨色字（`#23211d`），不使用高對比純黑純白。主要強調色：
- **青色（`#2d6173`）**：AI 討論、深度解析、外部超連結。
- **赭色（`#9c5f1c`）**：讀者自定義筆記、手寫註記與手動修訂版本。
- **劃線底色**：淡黃（螢光標記）；AI 引用的句子僅加底線，不填滿底色，避免與個人筆記混淆。
- **深色主題**：暖黑底（`#1a1917`），字重下調至 330，原頁 PDF 支援反相護眼顯示。

## 儲存為什麼可靠

1. **作者隔離職責分離**：後端翻譯引擎僅寫入 `paper.json`，深度剖析寫入 `report.json`，使用者筆記與修訂一律透過前端發送原子操作寫入 `reader.json`，互不衝突。
2. **本機佇列與樂觀更新**：使用者操作第一時間寫入瀏覽器 `localStorage` 佇列並渲染介面，待後端持久化確認後才自佇列移除；斷網、當機或服務重啟皆不遺失。
3. **冪等性與時間戳校驗**：所有批註、編輯與手寫操作均附帶時間戳與唯一序號，服務端使用檔案鎖 + 臨時檔案原子替換寫入。
4. **譯文版本衝突防護**：讀者修改段落時記錄基礎稿雜湊；後續若重新翻譯該頁，介面主動提示讀者選擇「覆蓋為新譯稿」或「保留我修訂的版本」。
5. **完全去中心化與 Git 友善**：每篇論文獨立成目錄，全量資料均為標準 JSON 與 Markdown，能直接透過 Git 或雲端同步盤進行個人版本控制。
